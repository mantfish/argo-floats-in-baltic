What This Measures

This is a forecast-skill scoreboard, not a float-piloting system. For every Argo profiling float in Danish/Baltic waters, the pipeline runs one simulated trajectory per ocean-current model (CMEMS Baltic Sea Analysis & Forecast, FCOO/GETM), advecting a virtual copy of the float forward using that model's currents and the float's own dive profile. When the real float actually surfaces and reports its GPS position, each model's simulated position at that exact timestamp is compared against the truth, and the distance between them is logged as that model's error for that event.

There is no state estimation, no covariance, and nothing here controls a real float — it's a deterministic replay used purely to see, retrospectively, which current model predicts float drift better.

Data Flow, End to End
One Pipeline Run, Step by Step

Every invocation of main.py (twice daily, via GitHub Actions, or manually) calls run.run() once. It loads all persisted state, performs four passes over the float registry, then writes everything back out.

1
Refresh cycle actions — _refresh_cycle_actions
For every live float, re-downloads Rtraj.nc fresh (force_refresh=True — GDAC's file grows in place) and re-derives its ControlAction (dive depth, cycle length, ascent/descent speed) across only the float's recent_cycles_for_vote (config: 5) most recent real cycles — not its full history, since floats get reprogrammed to a different cycle length mid-mission. Every numeric field takes the median across that window; park_mode is park_on_bottom only if every one of those recent cycles has Argo's own GROUNDED QC flag set (the float's own onboard determination of whether it touched the seabed that cycle) — a single non-grounded cycle in the window is treated as genuine uncertainty, not outvoted by a majority. Runs first so this round's own simulation already uses the freshest estimate.
2
Extend trajectories — _extend_trajectories
One download_model_data fetch per model (not per float), scoped to a tight bounding box around every active float's anchor and trajectory tip (_active_bounding_box). Each float's row is trimmed to strictly-after its own trajectory tip (trim_to_forecast_only) and advanced with simulate.simulate_cycle, which integrates with classic 4th-order Runge-Kutta rather than forward Euler, at an adaptive step size: fine (60 s) while descending, ascending, or communicating at the surface, and much coarser (up to 3600 s, clamped to never overshoot the next phase boundary) while at constant parking depth. Every current-field query is corrected against two failure modes that used to silently return exactly 0.0: a query shallower than a grid's shallowest real level now holds at that level instead of falling out of range (_clamp_shallow), and a query landing on a masked/land grid cell is filled from its nearest real neighbor instead of zeroed (_fill_masked_nearest) — the latter was, on real data, the dominant cause of legs that silently never moved. A model with nothing new beyond where a row already is gets frozen in place for this round (missed_model_pulls += 1) rather than backfilled. Each real model also runs a parallel shadow track with force_drift=True, so park_on_bottom floats still drift with the parking-depth current for comparison — never shown on the public leaderboard/map.
3
Reconcile against real Argo data — _reconcile_with_argo
Pulls the current Argo population (download_argo_floats_in_domain). A float missing from this pull gets missed_pulls += 1 (dead at 5 consecutive misses). A float with a new confirmed surfacing gets scored: each model's trajectory is looked up at the exact real surfacing timestamp (never "last point" — the simulated tip usually runs ahead of real time) and the haversine distance to the real position is appended to error_db, unless the float was overdue (10+ days since its last surfacing) — still reset, just excluded from scoring. Every model's trajectory is then reset to a single anchor point at the real surfacing — this is what makes phase (descending / parking / ascending) recoverable later purely from elapsed time, with no phase flag ever stored. The discarded leg's full simulated path is copied into leg_history immediately before the reset.
4
Register new floats — _register_new_floats
Any float present in this Argo pull but not yet in floats_db gets a fresh FloatRow built from its full cycle history (_build_new_float_row → cycle_extractor.extract_cycles + build_actions + mode_vote_action), or default_action() (5-day bottom-park fallback) if it has fewer than 2 usable historical cycles.
5
Persist & export
All seven state tables are written back to data/store/*.parquet (float_store.save_*), then web_export.export_floats and export_leaderboard flatten the in-memory state into docs/data/floats.json and docs/data/leaderboard.json — the only two files this page's and the map's frontend JavaScript ever fetch. The GitHub Actions workflow commits both the parquet state and the JSON export back to the repo.
Module Responsibilities
ModuleJobI/O
data_handler.py Fetches everything external: CMEMS currents, FCOO currents (depth-resolved dk/idk grids plus a dedicated near-surface product, fetched independently), Argo domain population, one float's full .traj/profile history. Network only — no simulation, no knowledge of FloatRow.
cycle_extractor.py Pure computation: turns a float's raw .traj history into per-cycle metadata, then a single representative ControlAction. park_on_bottom comes straight from Argo's own per-cycle GROUNDED QC flag — no bathymetry-based inference. No I/O — takes a local file path, returns dicts/dataclasses.
simulate.py Pure computation: builds current-field interpolators from fetched model data (three resolution tiers for FCOO — surface grid, then idk, then dk) and forward-integrates one trajectory leg with adaptive-step RK4. Defines ControlAction (imported by cycle_extractor). No I/O — deterministic, no randomness.
float_store.py Load/save the float registry and every history table, flattening dataclasses to/from parquet. Disk only — no fetching, no simulation.
web_export.py Flattens in-memory state into the two JSON files the static frontend reads. Pure function of its inputs → writes docs/data/*.json.
run.py Orchestrates the whole cycle above and owns every policy constant (thresholds, region bounds) sourced from config.toml. Calls every module above; the only one that knows about all of them.

Rules That Shape the Numbers You See
  • No "surfaced" flag anywhere. A trajectory just keeps advecting indefinitely on the same dive profile, repeating it, until a real Argo ping resets the anchor.
  • Scoring is forced by real data arriving, never by a model's own simulation deciding it has "surfaced."
  • Freeze-on-gap, not backfill. If no new model data arrives, that row simply isn't extended this round — there's no retroactive resimulation once better data shows up later.
  • Forecast-only trimming. Each model pull is trimmed to strictly after the previous issue time before extending a trajectory, so the leaderboard measures forecast skill, not a mix of forecast and analysis-grade accuracy.
  • Overdue floats (10+ days since last surfacing) are excluded from scoring but not killed — a fresh ping clears the exclusion for free.
  • Shadow tracks (_shadow suffix) mirror every real model with force_drift=True, to check the park_on_bottom assumption against reality — never surfaced on the public leaderboard or map.
  • A current-field query never silently reads as exactly zero anymore. A query shallower than a grid's shallowest real level holds at that level; a query landing on a masked/land grid cell is filled from its nearest real neighbor. Since park_on_bottom floats only advect during their brief non-parked window each cycle, either failure mode used to be able to freeze an entire multi-day leg at the anchor position — confirmed as the dominant cause of legs that appeared not to move at all.
  • park_on_bottom requires every one of a float's recent cycles to be Argo-grounded, not a majority. Getting this wrong is a qualitative fork, not a matter of degree — park_on_bottom skips advection entirely during parking, parking_depth doesn't — so a mixed recent history is left as genuine uncertainty (see shadow tracks above) rather than resolved by outvoting it.
